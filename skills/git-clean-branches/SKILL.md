# 清理 Git 分支

## 角色

你是分支清理专员：**只读盘点 → 交用户确认 → 才执行删除**。默认处于预览模式，未经确认不删除任何分支。

## 适用与边界

**适用**：清理已完全合并进基准分支的本地 / 远程分支；清理长期未提交的过期分支；仓库分支过多需要盘点整理。

**不适用（改用其他技能）**：

- 需要把分支回滚到历史版本 → `git-rollback`；
- 需要创建 / 删除 worktree → `git-worktree`；
- 需要提交工作区改动 → `commit-create`。

**范围外**：删除 tag、改写历史、清理 reflog / 对象（`reflog expire` / `gc --prune=now` / `filter-repo`）均不在本技能范围内。

## 要求

1. **先预览再删除**：首次执行一律只读，把「将删除的分支」清单交给用户；用户确认后才执行删除。
2. **保护分支不动**：删除前读 `git config --get-all branch.cleanup.protected`，命中的（支持 `release/*` 等通配符）一律排除；未配置时按默认保护清单排除（当前 HEAD、`main`、`master`、`develop`、`release/*`）。
3. **不删未合并分支**：本地删除默认用 `git branch -d`（未合并时 git 自行拒绝）。`--force`（即 `-D`）只在用户显式要求、且对具体分支逐条确认后使用。
4. **远程删除单独确认**：`git push origin --delete` 影响协作者，`--remote` 必须由用户明确要求，且在清单中与本地分支分段列出。
5. **不可逆动作停下等确认**：分支删除后仅能靠 reflog 短期找回，属不可逆操作——用户未应答时**不执行删除**，只输出清单。

## 参数

| 参数 | 含义 | 默认 |
|---|---|---|
| `--base <分支>` | 清理基准：已完全合并进该分支的分支才算「已合并」 | 自动识别 `main` / `master` |
| `--stale <天数>` | 额外找出最后一次提交距今超过 N 天的分支 | 不启用 |
| `--remote` | 同时处理远程分支 | 只处理本地 |
| `--dry-run` | 只列出将删除的分支，不执行 | **默认行为** |
| `--yes` | 用户已在本次对话中明确授权该清单时，跳过逐条确认 | 不跳过 |
| `--force` | 用 `-D` 强删未合并的本地分支 | 不启用 |

## 执行步骤

1. **同步远端**：`git fetch --all --prune`；失败不阻塞，但须注明「分支状态可能过期」。
2. **确定基准**：取 `--base`；未指定时按 `main` → `master` 顺序取存在的第一个，都没有则询问用户。
3. **读保护清单**：`git config --get-all branch.cleanup.protected`；为空时用默认保护清单。
4. **盘点**：
   - 已合并：`git branch --merged <基准>`；加 `--remote` 时另取 `git branch -r --merged <基准>`（排除 `<remote>/HEAD`）。
   - 过期（启用 `--stale` 时）：`git for-each-ref --sort=committerdate refs/heads --format='%(refname:short) %(committerdate:short)'`，筛出距今超过 N 天的分支。
   - 两段结果均剔除基准自身与保护清单命中的分支。
5. **出清单**：分「已合并」「过期」两段列出，每条给出分支名 + 最后提交日期 + 是否已推送；无 `--yes` 时**到此结束**，等待用户确认后再次执行。
6. **执行删除**（仅确认后 / 带 `--yes`）：本地 `git branch -d <分支>`（`--force` 时为 `-D`）；远程 `git push origin --delete <分支>`。逐条执行、逐条报结果；失败的（未完全合并、权限不足、被 worktree 占用等）单独列出原因，不静默。
7. **收尾**：`git branch --list` 复核剩余分支；若某分支删不掉且提示被 worktree 占用，提示转 `git-worktree` 技能处置，不强行删除。

## 验证

- 实际删除清单与用户确认过的清单**逐条一致**（不多删、不漏报）；条数对不上时先停下核对，不继续。
- 保护清单命中的分支一条都没被删（`git branch --list` 复核）。
- 未使用 `--force` 时，确认没有任何「未合并」分支被删除（`git branch -d` 的拒绝信息即为证据）。
- 远程删除逐条给出结果（成功 / 失败及原因）。

**判定口径**：四项均通过方可声明清理完成；任一项不通过时停下报告，**不静默放行**。

## 任务目标

安全地清理已合并 / 过期分支：待删清单经用户确认、保护分支与未合并分支未被删除、远程删除逐条有结果。

## 注意事项

- **任务跟踪按环境能力可选**：环境提供 `TodoWrite` / `Task*` 工具时用原生任务清单跟踪进度，否则退回对话内文本清单或落盘勾选（如 `tasks.md`）——形态与规则见 AGENTS.md「任务跟踪机制」小节，不硬性依赖任一形态。

- **默认 dry-run**：养成先预览再执行的习惯；预览输出的清单可直接作为下一步确认的依据。
- **动分支前先核 HEAD 与工作区**：任何分支操作前先 `git rev-parse --abbrev-ref HEAD` 与 `git status --porcelain`——确认当前分支不在待删清单里，且工作区没有未提交改动（脏工作区先提交或 stash，避免把承载改动的分支删掉）。
- **长期分支用 `--base`**：维护 `release/*` 等长期分支时，用 `--base <该分支>` 清理已并入它的特性分支，而不是把它当待删对象。
- **团队协作**：删除共享的远程分支前，提示用户先与协作者确认。
- **`--force` 是最后手段**：未合并分支意味着其中的提交将失去分支引用（只能靠 reflog 短期找回）。删除后如需找回：`git reflog` 找到该分支最后一次提交，再 `git branch <分支名> <sha>` 重建。
- **确认请求无应答时**：可逆动作（fetch、预览、盘点）按原计划继续；删除属不可逆动作，停下等待确认并在汇报中标明"该决策未获用户确认"。
