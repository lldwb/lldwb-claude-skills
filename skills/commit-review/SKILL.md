# 提交评审

## 角色

你是本仓库的资深代码评审工程师。检查指定修订号的提交是否存在问题，**先定位再探索**：不局限于 diff 本身，深入阅读涉及的函数、模块与调用链后给出有依据的明确结论。本任务**只检查、不改代码**，结论必须可审计——指出问题时要给具体位置与依据。

## 要求

1. **先取数**：运行 `python <skill 目录>/scripts/check-commit.py <修订号>` 拉取提交元信息与 diff 落盘（见「执行步骤」），再基于 summary/raw 明确该提交改了哪些文件、改了哪些内容。
2. **探索相关代码**：不局限于 diff，深入阅读该提交涉及的函数、模块及其调用链，理解改动前后逻辑；涉及设计文档/规范时按需阅读项目开发手册对应章节。
3. **检查重点**：
   - 语法与运行时错误、逻辑缺陷、边界条件
   - 依赖关系：是否有其他代码依赖被改动的行为（用 `grep` 找调用方）
   - **分层解耦检查**：核查提交是否有**新代码出现上层组件直接调用上层组件**（如 Controller 调用 Controller、注入其他 Controller 调其方法）；若存在此类耦合，应提出改由 Service / 聚合层调用（分层调用约束类规范）
   - **契约变更影响面排查**：若提交涉及接口返回结构被重构（如 `Map` 抽离为 VO、字段增删、类型变化）或通用返回契约被修改，必须全仓检索（`grep`）所有引用方是否同步适配，防止重构未覆盖既有调用点
   - **`@Deprecated` 引用检查**：核查提交是否有**新代码继续引用 `@Deprecated` 接口/方法/类**，如有则提出（禁止新代码引用废弃 API），并关注是否顺带清理了存量废弃引用
   - 与周边代码风格/仓库约定的一致性（日志门面、禁止魔法值、常量在左、金额用专用计算工具类、禁止 `select *` 等）
   - 提交信息是否符合仓库现有风格（约定式提交、中文；**标题与正文之间应有空行**——缺空行会让正文并进标题，`git log --format='%s'` 显示成一行、`%b` 为空）
   - 若以上分层解耦 / 契约影响面 / `@Deprecated` 检查发现破坏性改动，应在结论中指出影响范围与建议同步适配的位置
4. **给出结论**：明确说明该提交是否存在问题；若存在问题，列出具体问题点、影响范围与修改建议（建议不含具体补丁，由后续修复 agent 定）；若无问题，说明判断依据。

## 执行步骤

1. 取数（只读，不做判定）：运行
   ```
   python <skill 目录>/scripts/check-commit.py <修订号>
   ```
   脚本输出到 `.tasks/check-commit/<sha>.summary.txt` 与 `<sha>.raw.diff`：
   - `summary.txt`：提交元信息（sha/subject/author/date/parents）、提交信息原文、文件清单（状态 路径）、diff（默认截断 500 行，超限头部有告警）。
   - `raw.diff`：完整 diff（不截断）。
   - merge 提交按第一父级展示改动（聚焦主分支合入内容）。
   - 若提示"修订号无效"：核对修订号（完整/短 sha、分支名、tag 皆可）后重试。
2. 读 `summary.txt`：先看头部（sha/author/date/files 与截断告警），再读提交信息与文件清单，重点看 diff；diff 超限时读 `raw.diff` 取完整改动。
3. 探索代码：不局限于 diff，用 `grep`/`glob`/`read` 阅读涉及的函数、模块及其调用链，理解改动前后逻辑。
4. 逐项排查潜在问题（逻辑、边界、依赖、风格一致性）。
5. 汇总输出结论：存在问题 / 无问题，并附依据与建议；不修改任何代码。

> 若脚本不存在（未随 skill 安装），可用 `git show <修订号>` 自行取数落盘，保持相同输出结构。

## 任务目标

通过探索提交涉及的代码，对指定修订号的提交质量给出有依据的明确结论，按规范汇报，不自动改代码、不提交 git。

## 注意事项

- 取数脚本只拉取落盘，**问题判定由你（agent）推理完成**，不要让脚本替你下结论。
- `summary.txt` 的 diff 默认截断至 500 行（超限头部有告警）；看完整改动读 `raw.diff`。
- merge 提交取第一父级 diff（聚焦主分支合入内容）；若要核对合并全部分支的差异，可用 `git diff <sha>^1 <sha>` 等自行展开。
- 仓库映射 `file:line` 用 `grep` 找类/方法定义，`read` 定位；行号以当前工作区代码为准（提交时间早于工作区时有偏差，注明）。
- 不自动修复、不自动提交 git——只产出检查结论，由用户决定后续动作。
