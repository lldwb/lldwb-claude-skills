# 路由表模板与填充说明

本文件是 `spec-route` 技能的参考件：**项目侧**按此模板把自家开发手册的章节结构登记进来，之后每次查规范都按「场景 → 章节」直接定位，不必全文加载手册。

## 何时读本文件

- 首次为某项目建立规范路由时（按「填充步骤」产出项目自己的路由表）；
- 按段读取手册时（照抄「读取指引」的命令写法）；
- 路由表与实际手册结构不一致、需要校准时。

## 一、先登记权威源

| 项 | 内容 |
|---|---|
| 手册路径 | `<项目根>/<手册相对路径>` |
| 章节标题格式 | 例：`## <中文数字>、<章节名>`（按项目实际格式填写，供 Grep 用） |
| 章节总数 | `<N>` |
| 维护约定 | 规则变更请改手册本身；本路由表只登记章节位置，不复制规则 |

## 二、路由表模板

每个场景一行；`场景` 用改任务时自然想得到的说法（越贴近实际提问越好），`章节` 是手册里承载该规则的章节。

| 场景 | 章节 | 章节锚点标题（Grep 用） | 该章关键约束（仅关键词，不复制规则） |
|---|---|---|---|
| `<场景 1：例 新增/修改持久层映射文件>` | `<章序号>` | `## <序号>、<章节名>` | `<关键词 1>`、`<关键词 2>` |
| `<场景 2：例 定义异常与错误码>` | `<章序号>` | `## <序号>、<章节名>` | … |
| `<场景 3：例 数据库表结构变更>` | `<章序号>` | … | … |
| `<场景 4：例 接口契约变更的影响面排查>` | `<章序号>` | … | … |
| `<场景 5：例 提交信息结构与类型>` | `<章序号>` | … | … |
| `<场景 6：例 分层与调用约束>` | `<章序号>` | … | … |
| `<场景 7：例 编码约定（日志、魔法值、数值计算）>` | `<章序号>` | … | … |
| `<场景 8：例 权限与鉴权>` | `<章序号>` | … | … |
| `<场景 9：例 定时任务 / 消息消费>` | `<章序号>` | … | … |
| `<场景 10：例 国际化资源与 Key 约定>` | `<章序号>` | … | … |

> 表不必求全：只登记**会被反复问到**的场景（提交规范、分层约束、持久层写法、异常体系、数据库变更、编码约定这几类命中率最高）。遇到未登记的场景，按「读取指引」临时定位后**回填一行**，路由表随使用增长。

## 三、填充步骤

1. 取手册的章节目录（Grep 章节标题格式即可一次列出全部章节与行号）：

   ```bash
   grep -n "^## " <手册路径>
   ```

2. 按上表逐行登记：场景 → 章节序号 → 锚点标题（**与手册标题逐字一致**，Grep 才命中）。
3. 每个场景再扫一眼该章的小节标题，把最常用的约束关键词填进最后一列（关键词只作提示，不构成规则）。
4. 若项目存在**高频子规范速查**（常被同时问到的几章），在表尾补一行"高频组合"，如：`持久层 → 异常错误码 → 数据库变更 → 编码约定`。

## 四、读取指引（查规范时照此执行）

```bash
# 1) 定位章节标题，拿到行号（pattern 用路由表中的「章节锚点标题」）
grep -n "^## <序号>、" <手册路径>

# 2) 只读该段：从命中的行号开始读，读到下一章标题前为止
#    在 Claude Code 中用 Read 工具：file_path=<手册路径>, offset=<起始行号>, limit=<该章行数>
```

- **不要**一次性 Read 整本手册；章节很长时按小节再切一次。
- 章节内出现"见第 X 章"这类交叉引用时，按同法再定位一次，不做连锁全量加载。
- 在 Claude Code 中优先用 **Grep 工具**（`pattern` + `path` + `output_mode: content`）替代 shell grep。

## 五、输出格式

查完规范后按此结构回复，便于用户复核：

```
场景：<用户的任务场景>
权威源：<手册路径>

命中的约束：
1. <约束原句或紧贴原意的摘录> —— `<手册路径>:<行号>`
2. ...

关联章节（本次未展开）：
- <章节名> —— 若涉及 <条件> 需一并参照
```

最后一条固定写明：**"以上为权威源摘录，规则以手册为准"**——提醒读的人规则归属，而不是这份回复。
