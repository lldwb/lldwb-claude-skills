# code-optimize

代码优化（小范围）的标准工作流：先理解再动手，按模块规划并实施优化（保持对外行为不变），编译/测试验证后按 commit 专员规范提交 git。

## 使用

用户要求小范围优化代码（重复代码抽取、局部性能提升、可读性提升、命名与局部结构改进等）时自动触发；也可显式要求"用 code-optimize skill 优化"。

**边界**：结构性改造、分层/职责重构、实现迁移、批量同构改造（需要重构契约、测试基线与对抗性审查）用 `refactor`；新增或改变对外行为用 `feature-dev`；缺陷修复用 `bug-fix`。

## 能力

- 单点定义（SSOT）：常量/错误码/配置/规则只在一个权威位置定义，其余引用
- 先核可得性再动手：依赖的数据、字段、接口先确认真实存在再写代码
- 优化不改变既有行为（除非是明确的 bug 修复）
- 提交：commit 专员方式——构造中文提交信息，先向用户确认再提交
