# code-optimize

代码优化（小范围）的标准工作流：先理解再动手，按模块规划并实施优化（保持对外行为不变），编译 / 测试验证后按规范提交 git。

## 使用

用户要求小范围优化代码（"优化这段代码""抽取重复代码""局部性能提升""提升可读性""命名与局部结构改进""清理小范围代码"等）时自动触发；也可显式要求"用 code-optimize skill 优化代码"。

**边界**：结构性改造、分层 / 职责重构、实现迁移、批量同构改造（需要重构契约、测试基线与对抗性审查）用 `refactor`；新增或改变对外行为用 `feature-dev`；缺陷修复用 `bug-fix`；纯注释改动用 `comment-supplement`。

## 能力

- 先理解再动手：动手前读规范与相关代码，按"优化目标 → 优化方案 → 涉及文件"组织规划
- 单点定义（SSOT）：常量 / 错误码 / 配置 / 判定规则只在一个权威位置定义，其余引用
- 先核可得性再动手：改动依赖的数据、字段、接口先确认真实存在与格式，不凭假设
- 优化不改变既有行为（接口返回、页面交互、业务流程），仅改进可读性 / 性能 / 结构
- 越界即停：优化中发现的真实缺陷不夹带修复，单列报告转 `bug-fix`
- 编译 / 单测验证通过后提交；前端页面 / 组件改动按项目实际框架人工验证并说明范围
- 提交：默认直接提交并在汇报中列出 sha、文件清单与提交信息；含删除 / 重命名 / 生成物或拆分方案不唯一时，先给方案请用户确认

## 文件

- `references/optimize-checklist.md` — 优化点与风险自查清单（按需加载）

- git（提交）
- 项目自身的构建 / 测试工具（编译与单测验证，按项目实际选择）
