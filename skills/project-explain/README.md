# project-explain

结合具体项目讲解概念的工作流：先读项目代码与文档，再逐项讲清"是什么 → 在本项目怎么落地 → 关键代码位置（`file:line`）→ 常见坑与约定"，结论都有真实位置支撑、不臆造，只产出讲解不改文件。

## 使用

用户说"我不懂如下内容，给我讲清楚""结合这个项目讲讲 X""这块是怎么实现的，讲一下"时自动触发；也可显式要求"用 project-explain skill 讲解 <内容>"。

**边界**：要把讲解沉淀为项目文档用 `doc-sync`；要改代码按改动性质转 `bug-fix` / `code-optimize` / `feature-dev`。

## 能力

- 逐项结构：它是什么 → 在本项目怎么落地 → 关键代码位置（`file:line`）→ 常见坑与约定
- 区分通用知识与本项目特有约定：通用知识简要带过，项目特有约定展开讲透
- 输出格式：开头一级标题 + Markdown 分点正文 + 结尾"这是什么项目"小节（定位、技术栈、核心模块）
- 不臆造：代码里找不到依据的内容不写，查不到就明确说明（标注写法见 `references/explain-outline.md`）
- 结尾附本次引用的关键位置清单，便于跳转核对
- 只产出讲解内容：不改代码、不落文档

## 文件

- `SKILL.md` — 技能指令（唯一入口）
- `references/explain-outline.md` — 讲解产出模板：文章骨架、单项四项写法、结尾项目小节、引用位置清单与无依据标注示例

## 依赖

- 无（仅需读取项目代码与文档）
