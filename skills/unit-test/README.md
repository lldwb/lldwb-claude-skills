# unit-test

单元测试工作流（生成 / 修复失败两类）：生成类须覆盖主要逻辑分支与关键边界、可运行可通过；修复失败类先定位失败归属（测试代码 / 被测代码），默认只改代码、不自行执行测试，交用户执行验证。

## 使用

用户要求"给如下代码生成单元测试"，或给出失败的单元测试执行结果要求"保证这些单元测试可以通过"时自动触发；也可显式要求"用 unit-test skill 处理这批单测"。

## 能力

- 模式判定：生成（自行验证可运行）/ 修复失败（默认不自行执行，交用户验证）
- 用例设计：正常流程 / 边界 / 异常分支，依赖外部资源用 Mock 或测试替身隔离
- 失败归属判定：测试代码问题（预期写错、Mock 未打桩、用例相互依赖）vs 被测代码缺陷（超出单测范围时建议转 `fix-bug`）
- 约束：不为变绿而弱化断言或删用例；改动被测代码时显式声明对生产行为的影响
