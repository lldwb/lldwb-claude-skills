# unit-test

单元测试工作流（生成 / 修复失败两类）：生成类须覆盖主要逻辑分支与关键边界、可运行可通过；修复失败类先定位失败归属（测试代码 / 被测代码），默认只改代码、不自行执行测试，交用户执行验证。

## 使用

用户要求"给如下代码生成单元测试"，或给出失败的单元测试执行结果要求"保证这些单元测试可以通过"时自动触发；也可显式要求"用 unit-test skill 处理这批单测"。

**边界**：缺陷根因定位与生产代码修复用 `bug-fix`；完整需求开发流程（单测只是其中一步）用 `feature-dev`；结构性改造与重构用 `refactor`；只为测试代码可读性的整理用 `code-optimize`。

## 能力

- 模式判定：生成（自行执行至可运行可通过）/ 修复失败（默认不自行执行，交用户验证）
- 用例设计：正常流程 / 边界（空值、极值、临界）/ 异常分支，按等价类划分取舍；依赖外部资源用 Mock 或测试替身隔离
- 隔离策略：不依赖真实网络、时间、随机与执行顺序，用例间相互独立
- 失败归属判定：测试代码问题（预期写错、Mock 未打桩、用例相互依赖）vs 被测代码缺陷（最小改动并声明对生产行为的影响；超出单测范围转 `bug-fix`）
- 约束：不为变绿而弱化断言、删用例或改正确预期；新增测试依赖先说明；环境不可用不静默跳过、不伪造执行结果
