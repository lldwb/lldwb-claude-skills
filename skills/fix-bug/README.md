# fix-bug

Bug 修复的标准工作流：先理解再动手，按「问题现象 → 原因分析 → 修改方案 → 涉及文件」四段式定位，修改后编译/测试验证，最后按仓库规范提交 git。

## 使用

用户提出 bug（现象描述 / 报错信息 / trace_id / 复现步骤 / 涉及模块/页面）时自动触发；也可显式要求"用 fix-bug skill 修复这个 bug"。

## 能力

- 先读 `AGENTS.md` 与开发规范，按需加载相关章节
- 后端问题可结合 `log-diagnose` 排查日志；涉及业务数据状态时用 `db-query` 核对（生产只读）
- 验证：Maven/Gradle/npm 等按项目实际构建命令
- 提交：约定式提交、显式 `git add`、不自动 push/merge/PR

## 文件

- `SKILL.md` — 技能指令（唯一入口）
