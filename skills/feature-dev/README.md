# feature-dev

需求开发全流程工作流：需求分析 → 方案设计 → 规划文档 → 分层实现 → 验证 → 提交。

## 使用

用户提出新需求、新功能、新接口、新链路，或要求对既有链路做较大改造（跨前后端、涉及外部依赖与第三方组件），并要求"从需求分析做到落地""把方案总结出来再执行""先出方案再改"时自动触发；也可显式要求"用 feature-dev skill 完成这个需求"。

适用边界：

- **本技能**：从需求到落地的完整开发流程（含方案确认、规划文档、端到端实测闭环）
- `code-optimize`：既有代码的小范围优化（重复代码抽取、性能、结构、可读性）
- `fix-bug`：缺陷定位与修复

## 流程

1. **需求分析** — 读规范与代码，通读需求给出的参考实现及其上下游调用方，理清完整链路
2. **可行性核证** — 用证据确认三方组件能力、配置生效方式、外部服务协议行为、上下游契约（`references/feasibility-check.md`）
3. **澄清歧义** — 命名、路径、校验规则、取值边界等问题用问答交用户确认
4. **方案设计** — 需求理解 + 文件级改动清单 + 影响面 + 关键决策点；多路线时给对比矩阵，由用户决策
5. **规划文档** — 需要时写入项目文档目录，颗粒度参照既有文档，随实现进展更新
6. **分层实现** — 数据模型/DTO → 服务接口 → 服务实现 → 控制器/入口 → 前端/调用方，每层编译验证
7. **验证** — 编译 → 单测 → 前端语法 → 端到端实测；根因用证据说话（`references/e2e-verify.md`）
8. **收尾提交** — 残留检查 → 恢复临时配置 → 文档同步 → commit 专员式提交（支持压缩到指定提交 / amend）

## 能力

- 先理解再动手、先出方案再改，关键决策点交用户确认（人在环）
- 外部依赖能力与配置生效方式用只读手段核证（反编译、注解提取、最小复现），不凭假设
- 端到端实测取证：浏览器 MCP（网络请求 + 控制台 + 页面状态）、日志按 trace_id 定位、服务侧最小复现
- 分轮迭代：部署 → 实测 → 证据定位根因 → 修复 → 再测，每轮明确告知用户下一步操作
- 提交：约定式提交、显式 `git add`、不自动 push/merge/PR；按用户要求支持压缩提交/amend/排除前端与临时文件
- 交叉引用：日志排查用 `log-diagnose`、前端报错用 `frontend-error-diagnose`、单测用 `unit-test`、文档同步用 `doc-sync`、提交用 `commit-changes`

## 文件

- `SKILL.md` — 技能指令（唯一入口）
- `references/feasibility-check.md` — 动手前的可行性核证（三方组件 / 配置绑定 / 协议行为 / 契约）
- `references/e2e-verify.md` — 端到端实测与取证（部署节奏 / 浏览器取证 / 日志 / 收尾检查）
