# i18n-transform

国际化（多语言）改造的标准工作流：把硬编码文案改造为资源文件驱动，覆盖后端消息 / 前端文案 / 参数校验消息三条改造线；协调方只编排，改造与审查分离，重试超限转"需人工介入"清单。

## 使用

用户要求"把某模块做国际化/多语言改造""硬编码文案抽到资源文件""补齐多语言资源""参数校验消息做国际化"时自动触发；也可显式要求"用 i18n-transform skill 改造某模块"。

**边界**：新增或改变业务行为用 `feature-dev`；只修资源文件格式错误用 `code-optimize`；需要多模块 worktree 并行隔离时与 `module-batch` 组合。

## 能力

- 三条改造线：A 后端消息（错误码 / 异常 / 提示）、B 前端文案（标签、按钮、占位符、弹窗、面包屑、选项）、C 参数校验消息（校验注解 `message`）
- 编排流水线：扫描分批（单批 ≤ 5 文件，资源文件不计数）→ 逐批改造子代理 → 独立只读审查子代理（🔴 致命 / 🟡 警告分级）→ 独立验证子代理（Key 集合一致 / 编码 / 映射完整 / 命名规范）→ 汇总报告
- 改造与审查分离：审查与验证只读且不参与改造；修复由独立子代理按最小改动执行，修复后必须复审（重试 ≤ 2 轮，超限出"需人工介入"清单，不静默放行）
- Key 规范：命名结构、前缀归属、多语言资源文件 Key 集合一致、非拉丁字符值侧转义、追加不覆盖 + 改造前备份
- 零业务逻辑修改：只动文案与资源文件，签名 / SQL / 权限注解 / 校验参数一概不动
- 产出：改造报告、新增 Key 清单（原文/译文对照）、遗留问题报告（模板 `references/report-template.md`）

## 文件

- `SKILL.md` — 技能指令（唯一入口）
- `references/key-conventions.md` — Key 命名结构、前缀归属表、资源文件多语言三件套格式与编码规则
- `references/subagent-prompts.md` — 改造 / 审查 / 验证三类子代理提示词模板（含分级标准与报告格式）
- `references/report-template.md` — 改造报告与遗留问题报告模板

## 依赖

- 子代理调度能力（`Agent` 工具，`subagent_type: general-purpose`，后台执行 + 轮询）
- 项目构建工具（编译验证，命令以仓库 `AGENTS.md` 为准）
