# doc-sync

文档与代码同步的标准工作流（更新 / 修正两类）：由文档定位到对应代码，确认真实行为后更新文档或修正过期描述，只改与本次变更相关的部分，改完用只读子代理复核一致性。

## 使用

用户要求"根据文档找到对应代码、确认变更后同步更新文档""确保文档与代码实际行为一致"，或指出文档有错误、过期、与代码实际行为不符时自动触发；也可显式要求"用 doc-sync skill 同步这批文档"。

**边界**：文档改动伴随代码改造或新增功能用 `feature-dev`；代码本身需修复用 `bug-fix`；不涉及文档的纯代码优化用 `code-optimize`。

## 能力

- 两个入口同一流程：由文档找代码（更新）/ 由变更点反查受影响文档（修正）
- 先理解再动手：逐条比对「文档写的」vs「代码做的」，梳理变更点（新增 / 变更 / 删除 / 已废弃）
- 约束：只更新相关文档、不扩大范围、不写未实现的功能、格式遵循项目现有规范、不确定项交用户确认
- 只改文档不改代码：代码问题单独报告（需修复转 `bug-fix`）
- 复核：`Agent` 工具调度只读子代理（`references/verify-agent.md`），返回「文档位置 / 证据位置 / 是否一致 / 证据」清单；事实源不限于代码（外部仓库 / 日志 / 配置 / 会话记录等口径同一）；按同步方式调度，主代理核对证据后再采纳
- 提交：只提交文档文件；标题与正文之间空一行、多行走消息文件 + `git commit -F`；提交前扫敏感信息，提交后复核 `%s`/`%b` 已分离

## 文件

- `SKILL.md` — 技能指令（唯一入口）
- `references/verify-agent.md` — 文档一致性复核子代理提示词模板（逐条核对，只读不改）

## 依赖

- 子代理调度能力（`Agent` 工具，`subagent_type: general-purpose`）
- git（提交）
