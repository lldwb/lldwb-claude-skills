# comment-supplement

注释补齐与修正的标准工作流：补全缺失的类 / 方法 / 字段注释，修正不准确、过期、与代码实际行为不符的描述；**改动严格限定在注释层面**，不确定项先交用户确认。

## 使用

用户要求"补全缺失的注释""修正注释中与代码不符的描述"时自动触发；也可显式要求"用 comment-supplement skill 补齐这批文件的注释"。

**边界**：注释问题与逻辑、结构、接口改动并存时用 `bug-fix` 一并处理（本技能不允许在同一提交里混入代码改动）；对外行为不变的结构性改造用 `refactor`；小范围代码优化用 `code-optimize`。

## 能力

- 三类标记：缺失 / 不准确 / 过期，逐文件审查后按确认结果处理
- 铁律：不改业务逻辑、签名、注解、默认值与枚举取值等公开契约；无法判断意图的进不确定清单，不臆测
- 注释写法约定：写"为什么"与约束条件，不复述代码字面意思；不写废话注释与 TODO 式占位
- 自检：`git diff` 逐块确认改动都落在注释内、`git diff -w` 辅助判断、编译验证未破坏语法
- 大范围任务按目录 / 模块分批，不确定项逐批交用户确认；发现的代码缺陷单列报告转 `bug-fix`

## 文件

- `SKILL.md` — 技能指令（唯一入口）
- `references/comment-checklist.md` — 三类标记的判定标准、注释写法约定与反例、自检命令、不确定项清单格式（按需加载）

## 依赖

- git（提交与 `git diff` 自检）
- 项目构建工具（编译验证未破坏语法，命令以项目 `AGENTS.md` 为准）
