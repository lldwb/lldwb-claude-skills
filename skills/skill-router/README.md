# skill-router（技能路由）

## 使用

任务描述无法唯一确定技能时（用户未指定 / 多技能重叠 / 边界模糊），由 AI 判断给出推荐。

```
这个需求该用哪个技能？
帮我选个技能
不确定这个任务用哪个技能
```

输出：「推荐技能 + 命中依据（引用该技能 description 原句）+ 被排除的候选与理由 + 备选」；判断结果落在含删除 / 历史改写 / 强推等危险动作的技能时，把该技能自带的确认要求原样带上。

## 能力

- **盘点实际可用的技能**：只从发现路径（`~/.claude/skills/` 等）里实际存在的技能中选择，判断依据是各技能 `SKILL.md` frontmatter 的 `description`，不是技能名；
- **决策框架**：任务特征归类 → 候选 → description 边界互指排除 → 三问收敛（改不改代码？行为变不变？产出是什么？）→ AI 判断；
- **理由可追溯**：推荐与排除都有依据（引用 description 原句），用户可直接纠正；
- **不确认时 AI 判断**：用户没指定技能时直接给推荐，不问"你想用哪个"；两轮收敛不了列 2~3 个候选交用户拍板；
- **只判断不代执行**：输出止于推荐，目标技能的执行与确认流程在用户确认后由目标技能自己走；
- **不绕过安全流程**：推荐危险动作技能时带上它自带的确认要求。

## 文件

| 文件 | 说明 |
|---|---|
| `SKILL.md` | 技能指令（七节基准 + 输入） |
| `README.md` | 本文件 |
| `references/skill-catalog-template.md` | 按任务特征分类的路由表模板 + 通用决策口诀 + 易混对清单，项目有自定义技能时按表补行 |

## 依赖

无（纯判断技能，无脚本、无第三方依赖）。判断依赖各技能自身 `SKILL.md` 的 `description`——候选技能未安装时读不到，如实说明"该技能不在当前环境"，不凭空推荐。
