# 重构契约模板（SSOT）

契约是**本次重构的唯一规则源**：目标形态、范围与单元、不可变更项、命名归属、验证命令，全部只在这一份文件里定义。主代理、改造子代理、审查子代理、修复子代理**加载同一份契约**——子代理是全新上下文，不继承主代理已读内容，prompt 中必须给出本文件路径并要求其自行加载。

## 落盘位置

| 场景 | 位置 |
|------|------|
| 默认（过程产物，不入库） | `<项目根>/.claude/refactor/<重构名>-contract.md` |
| 项目要求契约作为长期规范留存 | 项目文档目录（提交时纳入，随代码演进同步） |

契约一经用户确认即为判定依据；**任何变更都要回到用户确认**，不得在改造过程中自行放宽。

## 模板骨架

> 按本骨架填写；与项目无关的章节可删，留空章节写"无"。示例均为占位符，按项目实际替换。

```markdown
# <重构名> 重构契约

## 1. 目标形态

- 现状：<当前结构长什么样，问题是什么>
- 目标：<改造后结构长什么样；每层/每类的职责边界>
- 参考实现：<同类已改造完成的样例（文件路径），改造者应对照其风格>

## 2. 范围与单元划分

- 范围：<待改造的对象清单（目录/文件/类/页面）>
- 单元划分：<一个单元 = 一组可独立改造且并发不冲突的文件；通常一个入口类/一个页面/一个模块为一个单元>
- 单元与产物映射：<每个单元改成什么、新产物叫什么名字、放在哪 —— 保证并发单元不写同一文件>
- 公共文件处理：<被多单元依赖的基类/工具/配置，是串行处理还是排除在范围外>

## 3. 不可变更项（冻结清单）

> 逐项核对用；改造后任何一项变化都必须有契约内的明确声明。

| # | 冻结项 | 说明 | 核对方式 |
|---|--------|------|---------|
| 1 | 对外路径/路由/URL | <入口地址一字不改> | 契约快照 + 审查 |
| 2 | 方法签名 | <方法名、参数列表、泛型> | 契约快照 + 审查 |
| 3 | 返回类型与返回内容 | <类型不变；返回内容的字段/key 逐项一致> | 审查逐字段核对 |
| 4 | 异常行为 | <抛出的异常类型、错误码、触发位置不变> | 审查逐方法核对 |
| 5 | 关键注解 | <权限/事务/校验/序列化注解保持在原位置> | 审查 |
| 6 | 视图名/模板路径/前端资源映射 | <字符串一字不差> | 审查 |
| 7 | 外部协议与数据格式 | <请求/响应结构、字段名、编码、分页约定> | 契约快照 + 测试 |
| 8 | <项目特有项> | <配置键、注册项、字典编码等> | <核对方式> |

## 4. 必须迁移 / 必须保留

> 按重构类型填写两侧边界；判断标准要可用"看到什么代码就归哪边"落地。

| 必须迁移到<新层>的内容 | 判断标准 / 典型代码形态 |
|---|---|
| <业务逻辑1> | <例：默认值填充、跨表查询、数据组装、复杂条件分支、数据转换、私有辅助方法> |
| <业务逻辑2> | <...> |

| 必须保留在<入口层>的内容 | 原因 |
|---|---|
| <路由/入参绑定/参数校验注解> | <属于入口层职责> |
| <渲染/响应包装/视图选择> | <依赖入口层基类或框架能力，新层不可用> |
| <安全注解/防重复提交/会话相关> | <框架在入口层生效> |

## 5. 命名与归属

- 新产物命名：<由原名推导的规则，如"原名去 X 后缀 + Y 后缀">
- 包/目录归属：<新产物放哪个包/目录>
- 复用既有产物：<若新产物已存在（前序改造或迁移遗留），是追加还是覆盖 —— 默认追加，禁止改写既有成员>
- 一对一约束：<一个入口对象对应且仅对应一个新产物（如有）>

## 6. 事务与异常约定（如适用）

- <新层的事务注解与读写标记规则>
- <错误表达方式：抛业务异常 vs 返回错误对象；由谁统一处理>
- <禁止事项：如新层不得返回响应包装类、不得返回无类型 Map>

## 7. 验证命令与完成标准

```bash
# 编译
<编译命令，如 mvn compile -pl <模块> -am>

# 基线/回归测试
<测试命令，如 mvn test -Dmaven.test.skip=false -pl <模块> -am -Dtest=<TestClass> -DfailIfNoTests=false>

# 分层/架构测试（如有）
<命令>

# 契约快照
python <skill 目录>/scripts/contract-snapshot.py capture --root <源码目录> --out <快照文件>
```

完成标准：<编译通过 + 基线/回归测试通过（既有无关失败按失败集合放行）+ 审查无严重与规范问题 + 契约快照差异均为预期内>

## 8. 依赖与资源

- 规则源：<项目开发手册章节 / AGENTS.md 章节 / 既有同类实现>
- 环境依赖：<测试所需的数据库/中间件是否可用；不可用时的替代验证方式>
- 已知坑：<项目内与本次重构相关的历史坑（如测试基类配置、并发文件冲突）>
```

## 编写纪律

- **只写确定的事实**：目标形态与冻结项都要能从代码/规范中找到依据；不确定的标"待确认"，交用户确认后再落笔。
- **可判定**：每条规则都要能被审查子代理机械核对（"看到 X 判为违规"），避免"代码要优雅"这类无法判定的表述。
- **规则与实现不重复**：项目已有规范（开发手册/AGENTS.md）时**引用章节号**，不复制正文（单点定义）；契约只补充"本次重构特有"的决策。
- **范围写死**：范围外文件明确"不动"，避免改造过程中范围蔓延。
