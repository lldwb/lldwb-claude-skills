# module-batch

多模块并行改造/批量任务：为每个待处理模块创建一个独立 git worktree，各起一个子代理在 worktree 内直接完成模块改造任务（修改代码、执行测试、按容错条款处理失败、按门禁验收后提交），全部完成后合并回主分支并按规范提交。

## 使用

用户要求"按模块批量改造/处理多个模块"、"多模块并行执行任务"、"按工作树隔离并行开发"时自动触发；也可显式要求"用 module-batch skill 并行改造这几个模块"。

**边界**：单个单元、不需要并行的结构改造用 `refactor`（由它定契约与测试基线，本技能提供 worktree 并行执行机制，多模块并行改造时二者组合）；小范围优化用 `code-optimize`；缺陷修复用 `bug-fix`；新增或改变对外行为用 `feature-dev`。

## 能力

- 阶段 0 前置检查（工具/资源/依赖/git 起点/任务说明完备性）→ 阶段 1 并行子代理（后台执行 + 轮询）→ 阶段 2 合并（先对比改动交集，公共文件冲突取并集）→ 阶段 3 收尾（收尾报告，删 worktree 留分支）
- 任务说明四要素：核心改造内容、测试命令、失败分类与容错条款、阶段门禁——缺项视为任务说明缺陷，先补齐再派发
- 改造与审查分离：独立只读审查子代理（对抗性，按严重/规范/建议分级）→ 独立修复子代理最小改动修复 → 复审，不得由改造者自证
- 失败不静默：单单元失败不影响其他单元，重试 ≤ 2 次，仍失败记「需人工介入」并继续；失败集合收尾对比（前后一致或缩小即未破坏行为）
- 子代理是唯一执行者（不通过任何外部 CLI 中转），prompt 自包含（worktree 路径 + 模块路径 + 任务说明 + 规则源），调度与执行分离
- 收尾报告按模板输出：改动清单、门禁与测试结果、审查发现、失败集合对比、重试统计、需人工介入项、worktree 与分支处置

## 文件

- `SKILL.md` — 技能指令（唯一入口）
- `references/lessons.md` — 经验教训速查（对照排查清单，示例经验按项目技术栈替换）
- `references/subagent-prompts.md` — 子代理提示词模板（模块任务说明 / 异常回报 / 审查 / 修复）
- `references/report-template.md` — 收尾报告模板

## 依赖

- git（worktree 支持）
- 子代理调度能力（`Agent` 工具，`subagent_type: general-purpose`）
- 各模块的构建/测试工具（按项目实际）
