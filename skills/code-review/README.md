# code-review

代码评审（多对象）：按评审对象分五种模式——提交评审、合并评审、模块评审、项目整体评审、架构评审，只检查不改代码。

## 使用

按评审对象触发：

- **提交评审**："评审某个提交/PR 的质量""检查提交是否符合规范""排查某次提交引入的问题""这次提交有没有问题"
- **合并评审**："这个 MR 能不能合""评审这次合并的改动""看看这个分支合进去都有什么"
- **模块评审**："评审这个模块的代码质量""我准备接手这个模块，帮我看看"
- **项目整体评审**："看看项目整体质量""给项目做个全面体检"
- **架构评审**："评估一下项目架构""看看分层与依赖设计合不合理"

也可显式要求"用 code-review skill 评审 <修订号 | 分支区间 | 模块路径>"。

**边界**：需要落地修复评审发现的问题用 `bug-fix`；只是把工作区改动提交到本地用 `commit-create`。

## 能力

- 五种评审对象先识别模式再取数（模式路由表见 `SKILL.md`），通用六维 + 对象专属维度两层核查
- 提交 / 合并评审：先取数（`scripts/review-fetch.py`，修订号或 `--range` 区间）再探索调用链，不局限于 diff；七维核查；结论二值（存在问题 / 无问题）
- 模块 / 项目整体 / 架构评审：Glob / Grep / Read 探索 + 只读子代理分片收集（一个单元一个子代理），按对象专属清单核查；输出分级报告（严重 / 规范 / 建议）+ 优先级清单，架构评审附演进建议
- 证据可回溯：每条判断指回 diff 行 / `文件:行` / 命令输出
- 只检查不改代码，不自动修复、不自动提交；merge 提交按第一父级取数，diff 超长读 `raw.diff`

## 文件

- `SKILL.md` — 技能指令（唯一入口）
- `references/review-checklist.md` — 提交 / 合并评审七维核查清单（含「合并评审差异点」节）
- `references/checklist-module.md` — 模块评审专属维度（内聚 / 接口稳定 / 重复 / 分层 / 测试 / 缺陷抽查）
- `references/checklist-project.md` — 项目整体评审专属维度（一致性 / 规范覆盖 / 债务分布 / 依赖 / 构建 / 安全 / 文档对齐）
- `references/checklist-architecture.md` — 架构评审专属维度（分层 / 依赖方向 / 边界 / 扩展点 / 演进风险 / 约定落实）
- `scripts/review-fetch.py` — git 取数脚本（修订号模式：`<sha>.summary.txt` + `<sha>.raw.diff`；区间模式：`--range <base>...<head>` 输出提交序列 + merge-base 聚合 diff；参数 `--out-dir`）

## 依赖

- Python 3、git
- 脚本缺失（未随 skill 安装）时：提交 / 合并模式降级为 `git show` / `git log` + `git diff` 自行取数落盘（等价命令见 `SKILL.md` 注意事项）；模块 / 项目 / 架构模式不依赖脚本。
