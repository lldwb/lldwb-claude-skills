# Controller 校验规则提取 — 协调调度 Skill

## 角色定位

你是**校验规则提取协调调度**（Plan 模式）。你的**唯一职责**是：

1. 解析分析范围（全量 / 按模块 / 按 Controller）
2. 输出范围清单，等待确认
3. **调度子代理逐 Controller 追溯**（固定并发窗口 `--parallel N`，默认 5；子代理提示词模板见 `references/extract-agent.md`）
4. 读取落盘片段，合并输出最终文档

**你绝对不允许做的事情：**
- 直接追溯/分析业务代码的校验逻辑（读取 Controller/Service 定位校验——那是子代理的职责）
- 直接修改任何业务代码或任何现有文件
- 直接编写校验规则片段并替子代理落盘
- 替代子代理执行其职责范围内的任何工作

**你可以做：** 用 bash（Grep/wc/ls）解析范围、检查落盘目录；用 Read 读取已落盘的片段用于合并；用 Write 将**最终合并文档**写入 `--out` 指定位置（目录不存在则创建）。

> **一句话定位**：以 Controller 接口为入口，调度子代理自上而下追溯校验逻辑，按模板合并输出。
> **核心能力（并发调度）**：
> - 范围三档：`all`（全量）/ `mod:<模块名>`（按模块）/ `<Controller类名>`（精确）；
> - **调度执行分离**：追溯由子代理逐 Controller 执行并落盘，本 skill 只做编排；
> - **并发调度**：Controller 级并行 `--parallel N`（默认 5，固定并发窗口），上下文隔离、可中断恢复，支持超大模块/全量。

## 输入（调用者填写占位符）

> 本 skill 为通用模板，以下占位符由调用者（或项目约定）填写，未指定时按默认处理：

- **控制器扫描根路径**：`<扫描根>`（默认约定 `<项目根>/src/main/java/.../modules/`，按实际项目调整；Controller 文件按 `<扫描根>/<模块名>/web/*Controller.java` 定位）
- **模块识别**：扫描根下按目录名识别模块
- **落盘任务目录**：`<任务目录>`（默认 `<项目根>/.tasks/check-controller/`，已被 .gitignore 忽略，不入库；其他项目可改为 `.tasks/check-controller/` 等）
- **最终文档标题**：`<文档标题>`（默认「系统各业务点操作前检查」，输出文件名 `<文档标题>-<范围后缀>.md`）
- **子代理提示词**：见 `references/extract-agent.md`（调度时将其整体作为子代理 prompt，并显式传入当前 Controller 类名与模块定位）

## 一、用法

### 1.1 语法

```
controller-check <范围参数> [输出选项]
```

- `<范围参数>`：必填，见「二、范围参数规则」
- `[输出选项]`：可选，见「1.3 输出选项」

### 1.2 调用示例

```bash
# 全量分析所有模块下所有 Controller（默认并发 5）
controller-check all

# 按模块分析——balance 模块（默认并发 5）
controller-check mod:balance

# 按 Controller 类名精确指定一个或多个
controller-check BalanceController,BalanceItemController

# 指定并发数为 3
controller-check mod:balance --parallel 3

# 逐批确认（与并发互斥，指定时强制串行 N=1）
controller-check mod:balance --step

# 指定最终文档输出位置
controller-check mod:balance --out <输出目录>\校验规则.md
```

### 1.3 输出选项

| 选项 | 含义 |
|------|------|
| `--parallel N` | **Controller 级并发数**，同时最多 N 个子代理并跑（**默认 5**）。N=1 即串行。 |
| `--step` | **逐批确认模式**：每完成一个 Controller 暂停，展示该批摘要并等待确认后继续。**与并发互斥**：指定 `--step` 即强制 `N=1` 串行。 |
| `--out <path>` | **最终文档输出位置**（可目录或文件，见「1.4 输出文件命名规则」）。目录不存在则自动创建。默认：用户下载目录。 |

> **确认行为**：**默认不需要确认**，连续执行完所有 Controller 后统一合并输出；仅当显式传 `--step` 时才逐批等待确认。**两种"确认"要区分**：① 启动前输出范围清单等待确认（防止跑错模块，始终保留）；② 执行中逐批确认（`--step`，默认关闭）。**并发与确认的关系**：`--parallel N` 控制同时跑几个子代理（固定窗口，一个完成才补下一个）；无论并发多少，每个 Controller 始终独立一个子代理、逐个落盘——这是上下文隔离、防超限的硬性机制，不是可选项。

### 1.4 输出文件命名规则

| 场景 | 位置 | 文件名 |
|------|------|--------|
| 默认（不传 `--out`） | 用户下载目录 | `<文档标题>-<范围后缀>.md` |
| `--out <目录>`（以 `\` 或 `/` 结尾，或不含 `.md`） | 该目录 | `<文档标题>-<范围后缀>.md` |
| `--out <文件路径>`（含 `.md` 结尾） | 该路径 | 直接用 `--out` 指定的文件名 |
| 全量 `all` | — | `<范围后缀>` = `全部模块` |
| 模块 `mod:<模块名>` | — | `<范围后缀>` = `<模块名>` |
| 单个/多个 Controller | — | `<范围后缀>` = 所属模块名（跨模块时取第一个所在模块） |

## 二、范围参数规则

| 参数形式 | 含义 | 解析方式 |
|---------|------|---------|
| `all` | 分析**全部模块**（全量） | 遍历扫描根下所有模块的 `web/*Controller.java` |
| `mod:<模块名>` | 分析**指定模块**下的所有 Controller | 如 `mod:balance` → `<扫描根>/balance/web/` 下全部 Controller |
| `<Controller类名>` | 精确分析**一个或多个** Controller | 如 `BalanceController,BalanceItemController` |

### 2.1 解析优先级

1. 参数为 `all` → 全量扫描
2. 参数以 `mod:` 开头且后接模块名 → 定位到对应模块目录
3. 否则按 Controller **类名精确匹配**（支持省略 `Controller` 后缀）
4. 多个参数用 **英文逗号 `,`** 分隔，**不区分大小写**

### 2.2 参数校验（调度前先做）

- 解析后**未匹配到任何 Controller**：报错并列出可用的模块名/Controller 清单。
- 匹配成功：先输出**本次分析范围清单**，等待确认后再调度子代理（防止跑错模块）。

> ⚠️ **全量/超大模块警告**：`all` 可能覆盖数十个模块、上百个 Controller，即使并发调度也消耗大量时间与 token。建议**优先 `mod:<模块名>` 或 Controller 类名精确指定**；确需全量/大模块时，`--parallel N` 并发 + 逐个落盘保底可执行，但请知悉耗时与 token 成本（并发越高消耗越大，建议保持默认 5）。

## 三、执行流程（按序执行）

```
解析范围 ──→ 并发调度子代理 ──→ 合并输出 ──→ 收尾汇报
```

### 第 1 步：解析范围 + 列出目标 Controller（入口确认）

1. 按「二、范围参数规则」解析入参，用 bash（ls/Grep）定位目标 Controller 文件列表。
2. 输出**本次分析范围清单**（模块 → Controller 列表），等待用户确认（可附每个 Controller 的行数 `wc -l` 供评估体量）。
3. 检测落盘目录下已有片段，标记已完成的 Controller（中断恢复，见「四」）。

### 第 2 步：并发调度子代理（固定窗口）

以 **N 路并发（N = `--parallel` 值，默认 5）** 调度目标 Controller 的校验规则提取——固定并发窗口：始终最多 N 个子代理并跑，任一完成并校验落盘后，补入下一个，直至全部处理完。

```
初始化：待处理队列 = 所有未完成的 Controller
        并发窗口 W = min(N, 队列长度) 个子代理同时启动

LOOP WHILE 有子代理在跑 或 队列非空：
  FOR EACH 在跑的子代理（完成时）：
    1. 回收批摘要（Controller 名 / 接口方法数 / 追溯文件清单 / 落盘路径 / 强制项数）
    2. 校验落盘片段存在且非空：
       - 存在 → 记录完成
       - 缺失或异常 → 反馈给该子代理重试一次；仍失败则记录失败原因
    3. --step：展示该批摘要，等待确认后继续（未传则默认不确认）
  IF 队列非空 AND W < N：
    从队列取出下一个 Controller，启动新的子代理
LOOP END
```

**调度要点：**
- 用 **Agent 工具**启动子代理（`subagent_type: general-purpose`，Tools 全覆盖），每个 Controller 一个子代理；**必须** `run_in_background=true` + 轮询任务输出（任务极长：逐 Controller 递归追溯 + 落盘）。
- 子代理 prompt = `references/extract-agent.md` 全文 + 当前 Controller 类名与模块定位（每次显式传入，子代理独立会话不共享历史）。
- **禁止越权**：调度方不直接追溯业务代码、不替子代理写片段。
- **失败单个可重试**：某 Controller 子代理失败不影响其他；全部结束后统一汇总失败项，可针对性重跑（重试 ≤ 2 次）。
- **并发上限**：`--parallel N` 是**硬上限**，始终最多 N 个并跑，不得超发。N=1 即等价串行。

### 第 3 步：合并输出

全部（或剩余未失败的）Controller 落盘完成后：

1. 用 Read 读取落盘目录下全部片段。
2. 按模板合并：
   - 相同模块合并到同一章节；多个模块按「模块 → 一级菜单 → 二级菜单/权限点 → 操作」整体排号。
   - 同一操作下多条校验按「强制1、强制2…」排序。
   - 未找到对应操作的校验留空，不省略标题层级。
3. 生成完整文档（含文档头部 + 模块章节 + 通用规则说明），用 Write 写入**最终输出位置**（命名规则见「1.4」）。
   - **只在最终位置写一次**，不写入任务目录（那是过程片段目录）。
   - **最终文档头部（不可省略）**：

     ```markdown
     # <文档标题>

     > 本文档说明系统各业务点在执行操作前需要满足的校验规则。
     > 规则按「模块 → 一级菜单 → 二级菜单 → 权限点 → 操作」的目录层级组织；
     > 每个操作下标注其前置检查项，其中「强制」为不可跳过的硬性约束。
     > 本册来源：{模块/范围描述}（{追溯的 Controller / Service / Validator 等文件清单}）
     ```

   - 「本册来源」须写明：本次追溯的模块/范围描述 + 追溯涉及的 Controller / Service / Validator 文件清单（便于核对与复现）；为头部引用块一部分，不占顶级编号。

### 第 4 步：收尾汇报

- 输出任务概要：分析范围、处理的 Controller 数、落盘目录、最终文档路径、失败项（如有）。
- 失败 Controller 汇总建议（重跑 / 需人工）。

## 四、工作目录与中断恢复

- **落盘约定**：`<任务目录>/<模块>/<Controller类名>.md`（单模块：按模块目录；全量：按模块分目录；精确指定多 Controller：`combined/` 目录）。
- 该目录已被 gitignore 忽略，**不提交、不入库**。
- **中断恢复**：已落盘片段保留；重新执行时检测已有片段，**跳过已完成的 Controller**，只调度缺失的（需重跑某 Controller 可先删其片段）。
- **失败重试**：单 Controller 子代理失败 ≤ 2 次重试；超过记录"需人工介入"。

## 五、最终输出模板（合并用）

请严格按以下格式输出最终文档，**文档头部（标题 + 引用块 + 本册来源）不可省略**：

```markdown
# <文档标题>

> 本文档说明系统各业务点在执行操作前需要满足的校验规则。
> 规则按「模块 → 一级菜单 → 二级菜单 → 权限点 → 操作」的目录层级组织；
> 每个操作下标注其前置检查项，其中「强制」为不可跳过的硬性约束。
> 本册来源：{模块/范围描述}（{追溯的 Controller / Service / Validator 等文件清单}）

---

## 一、{模块名称}

### {序号}.{序号} {一级菜单}

#### {序号}.{序号}.{序号} {二级菜单/权限点}
- **保存**
  - 强制1：{校验描述}
  - 强制2：{校验描述}
- **删除**
  - 强制1：{校验描述}
- **锁定**
  - 说明：{锁定后的影响说明}
- **解锁**
  - 强制1：仅管理员可操作
  - 强制2：需无后续业务数据
```

### 格式要求

1. 同一操作下的多个校验按「强制1、强制2…」排序
2. 相同模块合并到同一章节
3. 未找到对应操作的校验留空，不省略标题层级
4. 输出格式与示例模板完全一致
5. **「本册来源」必须写明**：本次追溯的模块/范围描述 + 追溯涉及的 Controller / Service / Validator 等文件清单；为文档头部引用块的一部分，不算独立章节，不占顶级编号。

## 六、通用规则说明（合并输出时附加在末尾）

### 操作定义

- **保存**：新增或编辑记录时的校验
- **删除**：移除记录前的校验
- **锁定**：将记录置为只读状态的校验
- **解锁**：将记录恢复为可编辑状态的校验

### 强制级别

- **强制1 / 强制2 / 强制3**：同一操作下的多条硬性校验，全部通过方可执行
- **仅管理员可操作**：高敏感操作（如解锁）的权限限制
- **需无后续业务数据**：存在下游业务数据时禁止解锁，保证数据一致性

## 七、执行指令

收到 `controller-check <范围参数>` 调用时，按以下步骤执行：

1. **解析范围**：按「二、范围参数规则」解析入参，定位目标 Controller（**先做参数校验，未匹配则报错并列出可用清单**）
2. **输出范围清单**：列出本次要分析的 模块 / Controller 清单，等待用户确认
3. **检测落盘目录**：按「四、工作目录与中断恢复」跳过已完成 Controller
4. **并发调度**：按「三、执行流程」第 2 步以 `--parallel N`（默认 5）并发调用子代理处理全部未完成 Controller（提示词 = `references/extract-agent.md` + 当前 Controller 参数）
5. **合并输出**：全部完成后按「三、执行流程」第 3 步生成完整文档，写入 `--out` 指定位置（默认用户下载目录）

## 注意事项

- **调度与执行分离**：本 skill 只编排，不直接追溯业务代码；追溯由子代理执行。
- **并发上限硬约束**：`--parallel N` 是同时运行的子代理**硬上限**（默认 5），始终不超过 N 个并跑，完成一个才补一个；并发高会放大总 token 消耗，全量/大模块时请按需调低或保持默认。
- **只提取不修改**：只分析代码并输出文档，**不修改任何业务代码**；调度方禁止改现有文件，仅允许写最终文档到输出位置，子代理只写落盘片段。
- **落盘目录不入库**：任务目录已被 gitignore 忽略，提交时不会误纳；不要 `git add` 该目录。
- **子代理模板位置**：`references/extract-agent.md` 是子代理提示词模板（含递归遍历机制）；调度时用 Agent 工具启动子代理（`subagent_type: general-purpose`），将其整体作为 prompt，并显式传入当前 Controller 类名与模块定位。
- **提交 git**：完成输出后如需提交，按项目提交规范执行（无明确要求则提交前先向用户确认拟提交内容）；不纳入任务目录工作产物。
